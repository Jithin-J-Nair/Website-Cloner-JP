## Implementation / validation

### Implemented

- **One generic route transaction:** `route-navigation.ts` registers one persistent shell owner. TransitionLink, MagneticPill, project Back and chapter portal use it; no link-local push timers or independent pathname/Back/footer curtain-release timers remain in the active tree. Duplicate activation is rejected; pending hide is cancelled by Escape or browser Back. A hung route releases input after 12 seconds **waiting for the commit**, not 12 seconds from the initial click. That distinction was caught and fixed in browser testing.
- **Actual native aperture:** two Canvas2D XOR arms, source dimensions/transforms, exponential diagonal-relative zoom, negative hide / positive show rotation and 1s active hide/show clocks. Removed the large visible route title and blue transition icon. No WebGL context, dependency or stock shader effect added. DPR is capped at 2 and long frame deltas at .1s; these are runtime safeguards rather than hardware/performance claims. The generic effect is separate from the existing case→case morph.
- **Commit/disclosure lifecycle:** hold covered until Next's pathname commit, then resume destination scene owners **under the still-covered aperture**. Wait for current DOM fonts/visible images, bounded by 1.5 active seconds; not an assertion that every GPU asset is loaded. The owner sleeps completely during a pending commit and in hidden documents, restores inert/aria-busy state and focuses the main content after normal completion. Canvas2D-unavailable uses an opacity fallback. Reduced navigation bypasses the aperture; live reduced changes consume the existing transaction, not a new push.
- **Native chapter charge:** empty at rest, direction/elapsed-time driven 2/s fill, .3s hold, −5/s reverse after hold and −.2/s idle decay. Observe existing document/Lenis position, never add another scroll engine. Supports wheel and touch, menu/modal/transition/visibility cancellation, offscreen reset, sleeping empty state and rearming after cancelled navigation. Explicit buttons remain usable in reduced mode. Removed focus-dependent clipping on Home/archive mobile portals; all three chapter portals now keep controls exposed and stable through pointer-down/focus/up.
- **Menu choreography only:** 5.5em / 7.75em travel, ±3.5° tilt, .5s curve, native 0/.02/.04/.06s open and .08/.06/.04/.02s close delays. Retained markup, active state, focus trapping, handlers, existing custom branding and permitted fonts. Did not change newsletter semantics/endpoints.
- **Case Contact navigation:** when no footer exists on a case page, route to `/#footer-section` and preserve the fragment, instead of unexpectedly launching mailto. Existing local About/Home/archive contact targets remain unchanged.

No scene shader/physics/assets, dependency, commercial-font policy, metadata, SEO, robots, analytics, newsletter behaviour or customized wordmark was changed in this pass. Unused historical `TransitionProvider.tsx` remains unmounted; it was not introduced as a second system.

### Failures found during development (not hidden)

- Initial transaction watchdog included expensive destination preparation and cancelled an otherwise delivered route. Moved the deadline to the actual pending-commit phase and clear it on commit. Delayed, hung and late-delivery browser scenarios pass afterward.
- Initial additional touch probe sent incomplete synthetic TouchEvents (`targetTouches` empty), producing Lenis errors. Replaced it with **real browser CDP touchStart/move/cancel**, retained the zero-error assertion, and close each scenario's context before the next to avoid simultaneous software-GPU workloads. No application scroll-library error was suppressed.
- Utility smoke initially assumed all six paths rendered internal pages. Actual route/source inspection established the existing Labs external redirect and intentional design-system 404; tests now assert those exact policies and never claim an external Labs render.
- Final review found a cancelled automatic portal could leave its one-shot latch armed. Added transaction-completion rearm and a retry assertion. A first follow-up tried rejecting all `defaultPrevented` wheels, but **Lenis legitimately prevents native wheel defaults**, so the real-wheel browser gate failed. Final version gates on the shell's complete transaction phase instead, allowing legitimate Lenis input while excluding preparation/reveal input. The final full production regression, including real wheel and cancel/retry, passes on the build named above.
